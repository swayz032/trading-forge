## 3. WHAT NOW HOLDS THAT DID NOT BEFORE

### item 1 — the validity gate computes SEMANTIC diagnostics
`getSemanticDiagnostics` is computed, and a failure yields **`TYPE_INVALID`** — an **outcome,
not a catcher** — which can never be credited as coverage. `AR-589`'s `failed_parse: 0` was
true and meant almost nothing: nothing could ever have failed there.

### item 3 — SINGLE DIAGNOSTIC OWNERSHIP
`attributed` now means **the named catcher fired AND every competing catcher stayed SILENT**,
asserted per subcase, with `failed_ownership` as its own reported and enforced class. A
node-level catcher CLAIMS its subtree; identifier-level catchers are suppressed inside it.

🛑 **A REGRESSION I INTRODUCED AND THEN MEASURED, REPORTED RATHER THAN QUIETLY REPAIRED:** the
first ownership build claimed `require(...)`, `eval(...)` and `createRequire(...)` as owned
nodes **but emitted no violation for them**, so the interior identifier was suppressed and
rows `41(b)`/`(c)`/`(e)` silently fell to `MISS_NOT_CAUGHT`. **Suppressing a catcher without
replacing it does not re-attribute a finding — it deletes it.** Fixed by making every owner
emit its own violation at claim time.

### item 4 — `createRequire` RESOLVED
A committed fixture-only declaration in `ambient.d.ts` — deliberately **not** node's real
signature, which would drag `@types/node` back in and re-open item 2's defect. Row `41(e)` is
now type-valid and attributed to `1b-S:dynamic-loading`.

### items 6 + 7 — THE MODULE SYSTEM IS AN EXECUTABLE INPUT, AND THE TWIN IS REAL

`R-544` measured that `admitSource` **THREW** on `.mjs`/`.cjs`. The mechanism, confirmed here:
with `allowJs` off those files were dropped from the program root, `getSourceFile` returned
`undefined`, and the next line threw `TypeError: Cannot read properties of undefined (reading
'statements')`. **An instrument fault, never a verdict.** All six extensions are now handled
without throwing.

★★★★★ **THE MODULE SYSTEM IS A CONTAINER AXIS, NOT A TEXT AXIS** — derived from the
effective-module tuple (extension + nearest `package.json` `"type"`) and **cross-checked
against TypeScript's own `impliedNodeFormat`.** Two independent paths to the same fact; a
disagreement is an enforced failure class, and they AGREE on every row.

```
TWIN ASSERTION (item 7)
  PASS  54 (twin.cts) vs G-src-container-twin-esm (twin.mts)
        sameBytes=true (131B) | CJS -> only-module-system=true | ESM -> admitted=true
  PASS  54(b) (twin.cjs) vs G-src-container-twin-mjs (twin.mjs)
        sameBytes=true  (96B) | CJS -> only-module-system=true | ESM -> admitted=true
```

★★★★★ **ONE SOURCE TEXT, TWO CONTAINERS, EVERY TEXT-LEVEL CATCHER SILENT IN BOTH.** `R-544`
convicted the previous row `54` because its "ESM twin" was the red **with one line deleted** —
the mutation run backwards. This twin differs by the file extension and nothing else.

⚠️ **The byte-equality is asserted on the bodies ACTUALLY SUBMITTED to `admitSource`, not on
the bodies declared in `corpus.mjs`.** That correction was found by `red-proof.mjs`, not by
review: the `twin` failure class **would not go red** while the check read the declaration —
it was asserting what the corpus says rather than what the rule was handed.

## 4. THE MISSES, ENUMERATED BY CLASS — ALL HONEST, NONE ABSORBED

**`miss_not_implemented` (3)** — `26(a)` `(b)` `(c)`. The design names a **dependency-boundary
(capability)** catcher and this prototype implements none. They DO go red, via
`1b-S:import-cardinality`, and **they are not counted.** Unchanged from `AR-589`.

**`miss_type_invalid` (6)** — the new class, and where the number fell.

| id | diagnostic | why it is not rescued |
|---|---|---|
| `34(d-u)` | `TS2304: Cannot find name 'undeclaredReader'` | see the split below |
| `52(a)`–`(d)` | `TS1117: An object literal cannot have multiple properties with the same name` | a duplicate-key literal cannot be made type-valid without deleting the duplicate — i.e. without deleting the defect |
| `54(c)` | `TS2532: Object is possibly 'undefined'` + `TS2540` | module-scope `this` is typed `undefined` under an ESM parse, so any use of it is a type error |

### 🛑★★★★★ THE `34(d)` SPLIT — FLAGGED IN `AR-590 §2a` BEFORE THE BUILD, RESOLVED HERE

`34(d)` is the row that **found a real bug in this rule on run one**: a free reference to an
UNDECLARED identifier went uncaught, because the check required
`checker.getSymbolAtLocation()` and an unresolved identifier has no symbol.

★★★★★ **AND IT CANNOT BE BOTH TYPE-VALID AND UNRESOLVED. THAT IS NOT A CHOICE, IT IS
ARITHMETIC:** an undeclared identifier is `TS2304` by construction. So the row was split:

- **`34(d)`** — the free reference **DECLARED** in the committed surface. Type-valid, still a
  genuine free capture (it resolves to neither the fixture nor a `lib.*.d.ts`). **COUNTED.**
- **`34(d-u)`** — the **UNDECLARED** form. `TYPE_INVALID`. **NOT COUNTED, retained in full.**

⚠️ **The unresolved branch remains implemented in the rule and is exercised by `34(d-u)` as an
honest miss. Deleting the row would have erased this corpus's single most valuable result to
make a number look better.** The desk should overrule this disposition if it disagrees — it is
the one place in this delivery where a re-classification could be mistaken for burial.

### ⚠️ A FINDING INSIDE THE MISSES, NOT A BOOKKEEPING NOTE

★★★ **Under the pinned surface, the COMPILER ITSELF owns three of these channels.** `TS1117`
rejects every duplicate-cooked-key form — including both escaped variants — and `TS2532`
rejects module-scope `this`. **Those channels are closed; they are just not closed by the
custom rule the design credits.** `A CHANNEL CLOSED BY A DIFFERENT MECHANISM THAN THE DESIGN
NAMES IS STILL A DESIGN THAT DOES NOT KNOW WHY IT IS SAFE.`
